01 · the problem

Installing Frappe by hand is a long, fragile ritual.

The official guide is dozens of steps, and every one of them has to match your OS, your Frappe version and whatever is already on the machine. One mismatch and you're reading tracebacks at midnight.

Exact versions, or nothing

Frappe 16 needs Python 3.14 (exactly), Node 24, MariaDB 11.8 and Redis — Frappe 15 needs Python 3.10 and Node 18. The system's own versions are usually wrong.

MariaDB is a minefield

utf8mb4 settings, root using socket auth, a password nobody wrote down, and on Ubuntu an AppArmor profile that silently blocks the database from starting.

Node.js mismatches

An older system Node makes bench start fail with "engine node is incompatible" — even after you installed the right one, if the terminal was already open.

Two benches collide

A second install reuses the same ports (8000, 13000, 11000) and the same database server — they can't run together, and their caches and job queues mix.

Upgrades break halfway

15 → 16 means switching branches, rebuilding the Python environment on a new version and migrating — in the right order, or it fails with a SyntaxError.

Production is another project

nginx, supervisor, the scheduler, HTTPS, a firewall, file permissions for www-data — and bench setup production can break other sites on the server.

Small things, big failures

Missing time-zone data (Asia/Calcutta), a patched-Qt wkhtmltopdf, a busy apt lock, a dropped connection mid-download.

Interrupted = broken

Stop half way and you're left with a half-made bench, a half-configured package and no idea what's done and what isn't.

02 · what it does

Ten stages. Every one checked.

It looks at what's already on the machine, plans an isolated environment, installs only what's missing, and refuses to call it done until the site actually answers.

03 · features

Built for the install that goes wrong.

A happy-path installer is easy. This one is designed around everything that can fail — and what to do when it does.

[1]

◉Isolated environments

Install it twice — nothing collides

  • Own MariaDB instance per install
  • Own Redis and ports (8001, 8002, …)
  • Own Node.js version via ./start
  • Proves other installs are untouched
[2]

◉Resume & self-heal

Interrupted? Run it again.

  • Ctrl+C saves progress — continue later
  • Fixes network glitches, apt locks, stale lists
  • Retries only steps that are safe to repeat
  • Falls back if a private database can't start
[3]

◉Failures that explain

Where · why · how to fix

  • Names the exact step that failed
  • Shows the real error line, not a traceback dump
  • Suggests the fix for 20+ known problems
  • Never rolls back or deletes anything
[4]

◉Respects existing Frappe

Keep · update · upgrade · alongside

  • Detects every bench on the machine
  • Upgrade 15 → 16 in place, after a full backup
  • Finishes an upgrade that stopped half way
  • Never drops a database or touches other benches
[5]

◉Production mode

From laptop to server

  • supervisor + nginx, served by your domain
  • Scheduler on, restarts on failure and boot
  • Let's Encrypt HTTPS & ufw firewall (beta)
  • Other nginx sites left untouched
[6]

◉Secure by default

Nothing piped into a shell

  • Downloads pinned to SHA-256 / git commit
  • MariaDB root is never changed
  • Passwords never on screen or in ps
  • Checks network exposure and file permissions
[7]

◉Verified, not assumed

20+ health checks

  • Database, Redis, Node, Python, assets
  • An HTTP request to the new site
  • Success screen says why it's ready
  • Warnings named, never hidden
[8]

◉A terminal you enjoy

Arrow keys, not y/N walls

  • Animated banner and progress track
  • Option cards, Yes/No toggles
  • Live spinner with the current log line
  • Plain output for CI and pipes
04 · architecture

Three layers, one hard rule each.

That's how a second install can't break the first — and why the installer can prove it.

SYSTEM LAYERshared · rule: add only

apt packages, MariaDB / Redis / nginx binaries, nvm, uv — installed if missing; never upgraded, reconfigured or removed.

ENVIRONMENT LAYERone per install · rule: owned, nothing shared
frappe16
bench + Python venv
Node 24 · ./start
MariaDB frappe-db@frappe16 :3307
Redis :13001 :11001 · web :8001
frappe15
bench + Python venv
Node 18 · ./start
MariaDB frappe-db@frappe15 :3308
Redis :13002 :11002 · web :8002
SITE LAYERFrappe's own · rule: one database per site, never dropped

Each site keeps its own database inside its environment's MariaDB instance.

06 · get started

One command. Three questions.

Needs Ubuntu 22.04+ or Debian 12+, a user with sudo, and Node.js only to start the installer — it brings the Node.js Frappe needs by itself.

Recommended

Always the newest version. Press y at “Ok to proceed?”.

$ npm create frappe@latest

With options

Everything after -- goes to the installer.

$ npm create frappe@latest -- \
    --env prod --version 16 \
    --domain erp.example.com

Without Node.js

Download a release, verify, run.

# from GitHub Releases
$ sha256sum -c SHA256SUMS
$ tar -xzf create-frappe-*.tgz
$ ./package/install-frappe.sh
